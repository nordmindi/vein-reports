# TradingAgents SaaS Service API

This service wrapper lets a private SaaS backend submit TradingAgents analysis jobs,
poll job status, and fetch generated report artifacts. Keep this service behind your
backend and protect it with the service-to-service `X-API-Key`; do not expose it
directly to browsers.

## Run

```bash
pip install -e .
uvicorn tradingagents.service.api:app --host 0.0.0.0 --port 8000
```

Or:

```bash
python scripts/run_service.py
```

Swagger UI and OpenAPI are generated by FastAPI:

- Swagger UI: `GET /docs`
- OpenAPI JSON: `GET /openapi.json`
- Health: `GET /health`

Optional environment variables:

```bash
TRADINGAGENTS_SERVICE_API_KEY=change-me
TRADINGAGENTS_SERVICE_REPORTS_DIR=reports/api
TRADINGAGENTS_SERVICE_CACHE_DIR=.tradingagents_service/cache
TRADINGAGENTS_SERVICE_MEMORY_DIR=.tradingagents_service/memory
TRADINGAGENTS_SERVICE_WORKERS=1
TRADINGAGENTS_STRICT_REPORT_VALIDATION=false
```

## Submit Report Job

```http
POST /v1/reports
X-API-Key: change-me
Content-Type: application/json
```

```json
{
  "ticker": "NVDA",
  "analysis_date": "2026-05-07",
  "report_tier": "pro",
  "selected_analysts": ["market", "social", "news", "fundamentals"],
  "llm_provider": "ollama",
  "deep_think_llm": "glm-5.2:cloud",
  "quick_think_llm": "glm-5.2:cloud",
  "max_debate_rounds": 1,
  "max_risk_discuss_rounds": 1,
  "output_language": "English",
  "user_id": "saas-user-id"
}
```

Response:

```json
{
  "job_id": "abc123",
  "status": "queued",
  "status_url": "/v1/reports/abc123",
  "pdf_url": "/v1/reports/abc123/pdf",
  "json_url": "/v1/reports/abc123/json",
  "dashboard_url": "/v1/reports/abc123/dashboard",
  "validation_url": "/v1/reports/abc123/validation",
  "evidence_url": "/v1/reports/abc123/evidence"
}
```

### Request Fields

| Field | Type | Notes |
|-------|------|-------|
| `ticker` | string | Required. Normalized to uppercase. |
| `analysis_date` | string \| null | `YYYY-MM-DD`; defaults to the service date. Future dates are rejected. |
| `selected_analysts` | string[] | Allowed: `market`, `social`, `news`, `fundamentals`, `supply_chain`. |
| `report_tier` | `free` \| `pro` | Defaults to `pro`. `free` forces `selected_analysts` to `["market"]`. |
| `context_bundle` | object \| null | Optional VEIN supply-chain context. Pro jobs auto-add `supply_chain`. |
| `llm_provider` | string \| null | Optional provider override. |
| `deep_think_llm` | string \| null | Optional model override. |
| `quick_think_llm` | string \| null | Optional model override. |
| `backend_url` | string \| null | Optional backend URL override for compatible providers. |
| `output_language` | string \| null | Optional report language hint. |
| `max_debate_rounds` | integer \| null | Must be at least 1. |
| `max_risk_discuss_rounds` | integer \| null | Must be at least 1. |
| `checkpoint_enabled` | boolean \| null | Enables LangGraph checkpoint resume for the run. |
| `user_id` | string \| null | Caller-owned user/job correlation id. |

## VEIN Supply-Chain Context

`context_bundle` uses schema `vein-context-v1`. When present on a `pro` job, the
service automatically includes the `supply_chain` analyst and persists the bundle
in final state as `vein_context_bundle`.

```json
{
  "ticker": "TSLA",
  "analysis_date": "2026-06-30",
  "report_tier": "pro",
  "context_bundle": {
    "version": "vein-context-v1",
    "primary_symbol": "TSLA",
    "has_graph_coverage": true,
    "company": {
      "name": "Tesla, Inc.",
      "symbol": "TSLA",
      "is_chokepoint": false
    },
    "anchor_elements": [{ "name": "Electric vehicles" }],
    "downstream_products": [
      {
        "name": "EV battery packs",
        "category": "energy",
        "hops": 1,
        "is_chokepoint": true
      }
    ],
    "related_companies": [
      {
        "symbol": "ALB",
        "name": "Albemarle Corporation",
        "via": "Lithium refining",
        "via_chokepoint": true
      }
    ],
    "chokepoints": [
      { "name": "EV battery packs", "category": "energy", "hops": 1 }
    ],
    "peer_tickers_for_news": ["ALB"],
    "watchlist_notes": "Focus on margin and battery supply",
    "generated_at": "2026-06-30T18:00:00.000Z"
  }
}
```

Guardrails:

- `context_bundle.primary_symbol` must match `ticker`.
- `has_graph_coverage: false` must not produce fabricated supply-chain claims.
- `supply_chain_report` is structural context only; it must not issue a buy/sell recommendation.
- Peer news from `peer_tickers_for_news` is supplemental and is not treated as direct company news.

Full VEIN details are in
[trading-report-service-vein-integration.md](./trading-report-service-vein-integration.md).

## Poll Status

```http
GET /v1/reports/{job_id}
X-API-Key: change-me
```

Statuses are `queued`, `running`, `completed`, and `failed`.

Completed response example:

```json
{
  "job_id": "abc123",
  "status": "completed",
  "ticker": "NVDA",
  "analysis_date": "2026-05-07",
  "decision": "INSUFFICIENT_EVIDENCE",
  "error": null,
  "markdown_path": "reports/api/abc123/complete_report.md",
  "pdf_path": "reports/api/abc123/TradingAgents_Report_NVDA_abc123.pdf",
  "pdf_url": "/v1/reports/abc123/pdf",
  "json_url": "/v1/reports/abc123/json",
  "dashboard_url": "/v1/reports/abc123/dashboard",
  "validation_url": "/v1/reports/abc123/validation",
  "evidence_url": "/v1/reports/abc123/evidence"
}
```

Job metadata is persisted under:

```text
reports/api/_jobs/{job_id}.json
```

This prevents polling from returning `404` after an API worker restart or when a
different process handles the status request.

## Download Artifacts

All artifact endpoints require a completed job and `X-API-Key`.

| Endpoint | Purpose | Incomplete job |
|----------|---------|----------------|
| `GET /v1/reports/{job_id}/pdf` | Download the generated PDF. | `409` |
| `GET /v1/reports/{job_id}/json` | Download the full final-state log JSON. | `400` |
| `GET /v1/reports/{job_id}/dashboard` | Download `dashboard.json`. | `409` |
| `GET /v1/reports/{job_id}/validation` | Download `validation_report.json`. | `409` |
| `GET /v1/reports/{job_id}/evidence` | Download `decision_evidence_bundle.json`. | `409` |
| `GET /v1/reports/{job_id}/metrics` | Download `cost_metrics.json` (LLM usage + cost estimate). | `409` |

Completed jobs also include a `metrics` summary on `GET /v1/reports/{job_id}` and
structured log fields on `report_job_completed` (`llmCalls`, `tokensIn`, `tokensOut`,
`estimatedCostUsd`). This schema is **application-neutral** — any consuming service
(Vein Explorer, Golden Trend, etc.) can ingest it for billing dashboards.

`cost_metrics.json` uses version `report-metrics-v1`. Override model pricing via
`TRADINGAGENTS_MODEL_PRICING_JSON` when your deployment uses custom rates.

The dashboard artifact is the canonical public summary for downstream apps. If
validation blocks transaction authority, it publishes:

```json
{
  "report_status": "blocked",
  "decision_status": "blocked",
  "recommendation": "INSUFFICIENT_EVIDENCE",
  "action": "NO_CURRENT_TRANSACTION"
}
```

The raw Portfolio Manager text remains available in logs and report sections for audit,
but dashboards and PDFs should use `dashboard.json` for transaction-facing status.

## Generated Report Directory

A completed job writes:

```text
reports/api/{job_id}/
  complete_report.md
  dashboard.json
  validation_report.json
  decision_evidence_bundle.json
  verified_claims.json
  rejected_claims.json
  validated_lessons.json
  TradingAgents_Report_{TICKER}_{job_id}.pdf
  1_analysts/
  2_research/
  3_trading/
  4_risk/
  5_portfolio/
```

Full state logs are stored under:

```text
reports/api/_logs/{job_id}/{TICKER}/TradingAgentsStrategy_logs/
```

## SaaS Integration Notes

- Keep end-user auth, subscriptions, billing, quotas, and report ownership in the SaaS backend.
- Treat this service as a private worker API.
- Store generated PDFs in object storage for production downloads. The current implementation writes to local disk.
- Start with `TRADINGAGENTS_SERVICE_WORKERS=1` unless provider rate limits and machine resources support parallel agent runs.
- For production, replace the local job store with a database table plus a queue worker such as Redis/RQ, Celery, Dramatiq, or a managed queue.
- Use `dashboard.json`, `validation_report.json`, and `decision_evidence_bundle.json` for product UI state instead of scraping Markdown or PDF text.
